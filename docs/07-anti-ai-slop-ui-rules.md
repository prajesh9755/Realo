# 07 — Anti-AI-Slop UI Rules

**What the UI must never look like.** These are prohibitions, not a design system. They
apply to anything generated by an AI tool as much as to hand-written code.

> **The design system itself is [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)** — palette, type
> scale, and component specs, all sampled from the reference screens in
> [`UI SCREENS/`](../UI%20SCREENS/). That file is what `src/styles.css` implements. This
> file only lists what to avoid.

> **History:** this document arrived from another project (a Flutter membership app) and
> carried that project's theming system, `AppTheme` references and Devanagari typography
> rules. Those never applied here and were removed 2026-10-12. The general anti-slop rules
> below did apply and are all that remains.

---

## 1. Core principle

The UI must look **hand-designed and specific to this product**, not like a generic
AI-generated template. A judge should not be able to tell it was built with AI assistance.

For this project that means: light, white, minimal. Near-black ink, one accent used
sparingly, generous whitespace, square product tiles. Restraint over decoration.

---

## 2. Explicitly avoid

| Pattern | Rule |
|---|---|
| Purple/blue neon glow gradients | Never, as background or card decoration |
| Dark "developer demo" theming | Not here. This is a storefront. White page, `--ink` text |
| Overused fonts (Inter, Geist, Space Grotesk, Roboto) | Not allowed. This project uses **Poppins** |
| Eyebrow numbers (`01`, `02` above headings) | Not allowed |
| Fake browser-chrome dashboard mockups | Not allowed. Real screenshots or none |
| Excessive em-dash chains in copy | Avoid. Use periods and commas |
| The same card-grid block repeated down a whole screen | Vary section structure |
| Emoji anywhere — UI text, buttons, status messages, errors | **Never.** SVG icons only |

---

## 3. Icon system

- One consistent **stroke-based set**, defined in [`src/ui/icons.js`](../src/ui/icons.js).
- Uniform `stroke-width: 1.5`, round caps and joins, `currentColor` so icons inherit text
  colour.
- **Do not mix icon sets.** Do not import a second icon library.
- **No emoji as icons**, anywhere, for any reason.

---

## 4. Typography

- **One family here: Poppins.** The general rule is a maximum of two per surface.
- Sizes and weights come from the scale in [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md), never
  chosen ad hoc per screen.
- Headings `600`, tight tracking (`-0.02em`), `line-height: 1.1`.
- Body `400` at `line-height: 1.6`.

---

## 5. Colour usage

- No gradient glows, no neon, no "AI SaaS" hero backgrounds.
- Backgrounds are solid. Product tiles are `--tile` (`#F3F5F7`), the page is white.
- Buttons use a solid fill from the tokens, never a gradient.
- **Never hardcode a hex value in a rule.** Everything comes from the `:root` custom
  properties so the palette stays changeable in one place.
- Secondary colours (blue, orange, red) are for state, not decoration. Green marks a
  discount or the true-scale badge; red marks an error or a broken scale guarantee.

---

## 6. Copywriting

- Plain, human language in errors and confirmations. No exclamation overload.
- No `01 / 02 / 03` styling above headings.
- No emoji in any message, including status lines and validation errors.
- **State limitations plainly rather than hiding them.** `try.html` says its cutout has no
  depth; the AR fallback explains why there is no camera. This is a product whose core
  claim is measurement accuracy, so overclaiming anywhere undermines it everywhere.

---

## 7. Layout

- Do not repeat an identical "icon + heading + paragraph in a card" block down a screen.
- Empty states are designed, never blank.
- **Never render fake or placeholder rows.** The generated silhouettes in `public/photos/`
  are an acknowledged exception, documented in [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md), and
  are to be replaced with real imagery.

---

## 8. Checklist

- [ ] One icon set, consistent stroke width
- [ ] No emoji in any UI text or error message
- [ ] Colours from tokens, no hardcoded hex
- [ ] Poppins only, sizes from the type scale
- [ ] White page, `--ink` text, no dark theme
- [ ] No gradient glow backgrounds
- [ ] No fake dashboard or browser-chrome mockups
- [ ] No eyebrow numbering
- [ ] No repeated identical card-grid sections
- [ ] Every list has a designed empty state
- [ ] Limitations stated plainly, not hidden

---
